## 两个必须理解的设计决定

### 1｜小程序端不直连数据库，云函数是唯一写入口

云函数用 admin 身份访问数据库，**会绕过安全规则**。因此"非成员无法读取队伍位置"
不可能靠数据库安全规则实现，必须在 `lib/authz.js` 里显式校验，且**不缓存成员身份**——
这样"退出后立即失去访问权"自动成立。

安全规则请按 `docs/项目计划书.md#data-model` §0 决定 1 配置：只有 `places` 允许小程序端读。

### 2｜仓储层可替换，算法与存储解耦

`lib/repo/memory.js`（本地测试）与 `lib/repo/cloud.js`（云数据库）实现同一接口。
`domain/` 下的算法只依赖该接口，不 import `wx-server-sdk`。

**推论是一条开发纪律**：任何业务逻辑都不许写进云函数入口。
入口只做三件事：取身份、选仓储、调用 `lib/invoke.js`。
否则本地测试跑的不是线上真正执行的代码。

### 订阅消息（2026-10-17）

三个模板的 ID 与字段编号固定在 `cloudfunctions/api/lib/subscribe/templates.js`（集合 `thing1/thing2/time3/thing5`、状态变更 `thing1/thing2/thing3/time4`、未读提醒 `thing2/time3/thing4`），**不要在前端或别处再写一份**——两处漂移的表现是"点了订阅没反应"。发送走 `cloud.openapi.subscribeMessage.send`，密钥由云开发代持，不要给客户端下发 AppSecret 或 access_token。

部署后必须人工确认两件事，否则发送会以"没有权限/模板不存在"失败，而本地测试用的替身**测不出这一类问题**：

1. `api/config.json` 的 `permissions.openapi` 含 `subscribeMessage.send`（已写入；上传部署后到云函数配置里核对一眼）。
2. 三个模板在用户小程序后台处于**启用**状态，且字段编号与 `templates.js` 一致。

行为边界（代码现状，不代表已送达）：一次授权约等于一次额度，`subscribe.report` 只记"用户同意过"，真实能否发送以微信返回为准；微信回 43101（未订阅/次数用尽）时把意向标记 `revoked`，云调用抛异常记 `unknown` 且**不自动重试**；聊天通知按 60 秒窗口合并，已读的人不再提醒；通知失败不影响已落库的聊天与集合。自动化回归注入 `lib/subscribe/fake.js`，**不要拿真实订阅次数做探针**。

本轮目标是体验版修复。昵称与头像的内容安全、微信邀请分享尚未实现，保留为正式发布前待办；本轮不宣称具备正式发布条件。公共交通继续采用线路、时间与总费用的简洁摘要。

位置共享入口为「我的 → 设置 → 自动共享位置」。开启后前台自动定位，移动时按 15 秒节奏处理、位移至少 20 米才上传，静止每 60 秒更新；进入「队伍」立即更新，切到后台暂停。`app.json` 已声明前台持续定位接口，微信平台的定位接口权限与隐私用途需与实际使用保持一致；不申请后台定位。集合时间选择器默认当前时分，仍由用户手动调整到未来的集合时间。

### 定时触发器（位置保留策略）

`timer-cleanup` 必须配置定时触发器，建议**每小时一次**，否则
"精确位置短期保留"这条隐私承诺在代码里没有执行者。

**配置方式（2026-10-15）**：`cloudfunctions/timer-cleanup/config.json` 里已声明
