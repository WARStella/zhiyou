# 智游·灵动｜后端（B 负责）

微信云开发：**云函数 + 云数据库**。本目录是 B 的完整后端工程。

```
zhiyou/
├── cloudfunctions/
│   ├── api/                 统一入口云函数（唯一业务入口）
│   │   ├── index.js         云函数入口：取微信身份 → 选仓储 → 交给 invoke
│   │   ├── lib/             框架层：错误码、响应、时间、地理、鉴权、幂等、仓储
│   │   ├── domain/          领域层：纯函数算法（时间线/可行性/规划器/集合）
│   │   ├── actions/         接口层：按域拆分的 action
│   │   └── lib/map/         地图 provider（腾讯 / 假数据 / 真实录音回放）
│   └── timer-cleanup/       定时清理过期位置与幂等记录
├── docs/
│   ├── 01_数据模型_v1.md    ★ 唯一事实来源：14 个集合 + 错误码 + 冲突码
│   ├── 02_接口清单_v0.md    云函数 action 清单（10/15 冻结）
│   └── 00_今日行动_1013.md  当日工作计划
├── test/                    本地测试（内存仓储 + 真实 invoke 路径）
└── scripts/                 测试入口与校验脚本
```

## 快速开始

```bash
# 运行全部测试（约 1 秒）
node scripts/run-tests.js

# 也可以用标准运行器（不受沙箱限制的环境下）
node --test test/
```

测试**不需要 AppID、不需要云环境、不需要联网**。这是刻意的设计：领域算法是纯函数，
仓储层可替换（本地内存 / 云端数据库），因此算法可以在拿到 AppID 之前就完成开发与验证。

## 两个必须理解的设计决定

### 1｜小程序端不直连数据库，云函数是唯一写入口

云函数用 admin 身份访问数据库，**会绕过安全规则**。因此"非成员无法读取队伍位置"
不可能靠数据库安全规则实现，必须在 `lib/authz.js` 里显式校验，且**不缓存成员身份**——
这样"退出后立即失去访问权"自动成立。

安全规则请按 `docs/01_数据模型_v1.md` §0 决定 1 配置：只有 `places` 允许小程序端读。

### 2｜仓储层可替换，算法与存储解耦

`lib/repo/memory.js`（本地测试）与 `lib/repo/cloud.js`（云数据库）实现同一接口。
`domain/` 下的算法只依赖该接口，不 import `wx-server-sdk`。

**推论是一条开发纪律**：任何业务逻辑都不许写进云函数入口。
入口只做三件事：取身份、选仓储、调用 `lib/invoke.js`。
否则本地测试跑的不是线上真正执行的代码。

## 部署到云开发

1. **注册小程序拿 AppID**（个人主体即可，无需 300 元微信认证）。
2. 微信开发者工具导入本目录，把 `project.config.json` 的 `appid` 换成真实值。
3. 云开发控制台**先建一个环境** `zhiyou-dev`；套餐允许时再建 `zhiyou-prod` 用于正式实测。
   环境ID 创建后不可修改。详见 `docs/05_小程序基本信息填写.md` 与「环境与套餐」说明。
4. 右键 `cloudfunctions/api` → 上传并部署（云端安装依赖）。
5. 云函数配置（在**云开发控制台 → 云函数 → api → 配置**里改，不在 `config.json` 里）：
   - **超时时间**：默认很短（数秒），**必须改成 20 秒**
   - **环境变量**：
     | 名称 | 值 | 说明 |
     |---|---|---|
     | `ZY_ENV` | `dev` | 控制 `ops.initDb` 等运维接口是否可执行；正式实测期改 `prod` |
     | `ZY_ADMIN_OPENIDS` | 你的 openid（多个用逗号分隔） | **运维/探针接口的白名单**（2026-10-15 加）。⚠️ **不配 = 全部拒绝** |
     | `MAP_KEY` | 腾讯位置服务的 Key | **只存在于此，绝不进代码或仓库**（11/12 验收项） |
     | `AI_API_KEY` | DeepSeek 的 Key | 需求解析用；**没配就自动降级到规则解析**——那时 AI 相关的验证都测不出来 |
     | `MAP_PROVIDER` | 可留空 | 留空默认 `tencent`；本地/联调可设 `fake` 走假服务 |

   > **`ZY_ADMIN_OPENIDS` 为什么要 fail closed（没配就拒绝）**：
   > 这些接口原本只靠 `env === 'dev'` 把关，而环境判定是宽松的
   > （`index.js`：`ZY_ENV` 没配成 `prod` 就算 `dev`）。体验版一发给测试者，
   > `place.survey`（**写地点核验等级**）、`ops.exportWalkSamples`（导出地点名）
   > 就对所有体验成员开放了。
   >
   > "没配就当没限制"是最糟的默认值 —— 它会让守卫在**真正需要它的那一刻**
   > （刚部署、还没配变量）恰好失效。所以不配就拒绝，并**把你自己的 openid
   > 放进错误信息**，复制到环境变量里即可（见 `lib/ops-guard.js`）。

   > `config.json` 只放**经过验证**的字段（当前仅 `permissions.openapi`）。
   > 我无法确认 `timeout` 是否为 `config.json` 的合法字段，因此不写进去 ——
   > 一个不受支持的键可能在部署时抛错，而部署恰恰是最不该出岔子的时刻。
   > 若后续确认支持，再补回不迟。
   >
   > 后续接入内容安全（`cloud.openapi.security.msgSecCheck`）时，
   > 需要在 `config.json` 的 `permissions.openapi` 中登记对应权限。
6. 调用 `ops.initDb`（`{confirm: true}`）创建全部集合，它会返回**需要手工创建的索引清单**。
   **它不会灌入任何地点** —— 地点只来自上游检索与 10/16 踏勘录入。
   云开发无法通过 SDK 建索引，必须在控制台逐个创建。

### 定时触发器（位置保留策略）

`timer-cleanup` 必须配置定时触发器，建议**每小时一次**，否则
"精确位置短期保留"这条隐私承诺在代码里没有执行者。

**配置方式（2026-10-15）**：`cloudfunctions/timer-cleanup/config.json` 里已声明
（`triggers` 字段，官方核实的字段；cron **7 段**：`0 0 * * * * *` = 每小时整点）。
⚠️ **上传部署后必须去控制台确认触发器真的出现在列表里** ——
本地写了不等于线上生效，而"我们配了定时清理"在材料里成立、在环境里不成立，
正是 §11.4 要防的那种落差。
若 `config.json` 的方式没生效，就改用控制台
（云函数 → timer-cleanup → **定时触发器** → 填同一段 JSON）。

| 项 | 值 | 说明 |
|---|---|---|
| 位置数据保留 | **7 天**（`actions/loc.js` 的 `RETENTION_DAYS`） | 材料里请写**具体天数**，不写"短期" |
| 幂等记录保留 | **24 小时**（`lib/idem.js` 的 `TTL_MS`） | 覆盖任何重试窗口 |
| 建议执行超时 | **20 秒** | 清理是"最多 50 轮 × 每轮 100 条"的循环，默认 3 秒在数据多时会被掐断 |
| 环境变量 | **不需要** | 它直接用 `wx-server-sdk` 操作数据库，**不经 `invoke`**，因此不受 ops 白名单影响 |
| 建议索引 | `locations.expiresAt`（非唯一） | 见 `ops.initDb` 返回的手工索引清单；不建则每次清理全表扫 |

## 参数冻结

`lib/params.js` 的 `algoVersion` 是**冻结锚点**。任何参数改动必须同时提升该版本号，
并写入 `events`。正式实验期间不得静默修改（计划书第四周纪律）。
