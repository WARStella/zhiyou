# 智游·灵动｜真机实测清单

> 这份文档是**给人在手机上照着做**的操作手册：每一节一个场景，写清「前置条件 → 怎么点 → 应该看到什么 → 什么算过、什么算不过」。
>
> 它补的是自动化测试覆盖不到的那一层：真机渲染、云数据库、微信真实发送、真实上游服务（见 [测试说明](测试说明.md) 第四节「不覆盖什么」）。**本地 1082 条测试全绿，不代表这里的任何一条自动通过。**
>
> 按钮文案取自 `miniprogram/**/*.wxml` 的真实文本，与真机界面一致；若界面已改动而本文没跟上，以界面为准并回来修本文。

---

## 〇、怎么用这份清单

1. **按编号执行**，不要跳着做：后面多数用例依赖前面已经建好的队伍、行程与集合。
2. 每条都有「结果」列可填：`通过 / 失败 / 跳过（附原因）`。
3. 失败时记三样东西：**哪一步、屏幕截图、当时后端日志或接口返回**。只写"不行"无法定位。
4. 分两个阶段：**第 1 阶段（P0）** 不通过就不要往下做；**第 2 阶段（P1/P2）** 可以并行、可以分批。
5. 涉及两台设备的用例，标注了 `[双机]`；三台标注 `[三机]`。

## 一、环境与账号准备

### 1.1 部署前置（在电脑上完成，不是真机操作）

| # | 事项 | 怎么确认 | 不做的后果 |
|---|---|---|---|
| P-01 | `api` 云函数已上传并部署（云端安装依赖） | 云开发控制台 → 云函数 → `api` → 版本时间是最新的 | 新接口报"未知的接口" |
| P-02 | 云函数超时改为 **20 秒** | 云函数 → 配置 | 集合推荐/AI 类调用被掐断 |
| P-03 | 环境变量齐全（`ZY_ENV`、`ZY_ADMIN_OPENIDS`、`MAP_KEY`、`AMAP_KEY`、`AI_API_KEY`） | 云函数 → 配置 → 环境变量 | 地图/公交/AI 全部降级或拒绝 |
| P-04 | `ops.initDb` 已执行（`{confirm:true}`） | 返回 `manualIndexes` 清单 | 集合缺失，写入报 `-502005` |
| P-05 | 按清单**手工**建了唯一索引 | 控制台 → 数据库 → 各集合 → 索引 | 防重复失效（同一条消息发两条、重复入队） |
| P-06 | `api/config.json` 的 `permissions.openapi` 含 `wxacode.getUnlimited` 与 **`subscribeMessage.send`** | 部署后到云函数配置核对 | 小程序码/订阅发送报"没有权限" |
| P-07 | 三个订阅模板在小程序后台**已启用**，字段编号与 `lib/subscribe/templates.js` 一致 | 小程序后台 → 订阅消息 | 发送报 `47003` 或模板不存在 |
| P-08 | 隐私指引已按实际用途补全（位置、录音、相册） | 后台 → 用户隐私保护指引 | 审核不通过；录音/位置弹窗异常 |

> **P-06/P-07 是订阅消息的硬前置**：本地测试用的是替身，测不出这两类失败。若 P-07 未就绪，第八节的用例全部标"跳过"，不要标"通过"。

## 二、第 1 阶段：P0 连通性（不通过就停下）

### 2.1 打开小程序不白屏

- **操作**：A 手机冷启动小程序。
- **预期**：直接进入「行程」tab（底部三个 tab：**行程 / 队伍 / 我的**），不白屏、不卡在加载文案。
- **判定**：任一 tab 可切换且有内容即通过。白屏 = 不过，先查基础库版本与 `app.js` 云开发初始化。
- **常见失败**：基础库过低（`wx.cloud` 不存在）→「我的」页会出现明确的云开发初始化错误文案。

### 2.2 后端自检

- **操作**：「我的」→ 底部「打开联调自检」→「后端自检」。
- **预期**：返回 `ok: true`，能看到 `env`、`deps.mapService / transitService / photoService / llm / subscribeMessage` 的 `configured` 状态。
- **判定**：
  - `ok:false` 且提示未取到身份 → 登录链路问题；
  - `configured: true` 只表示**配置存在**，不代表 Key 有权限 —— 别在这一步就下结论。
- **注意**：`subscribeMessage.configured` 恒为 `null`，这是刻意的（它不需要环境变量），不要把它读成"没配好"。

### 2.3 数据库与索引

- **操作**：同一页 →「初始化数据库」→「唯一索引校验」。
- **预期**：初始化返回集合清单与 `manualIndexes`；索引校验逐条报"已生效"。
- **判定**：有任一唯一索引报未生效 → **停下来手工建**，否则后面的"防重复"用例会假通过。

## 三、个人行程（A 单人即可）

### 3.1 首次规划：搜地点 → 确认 → 生成行程

- **前置**：A 没有进行中的行程。
- **操作**：行程页输入框输入 `想去哈尔滨学院` → 点搜索 → 在候选里点「确认这个地点」→ 选出发方式/时长 → 生成路线。
- **预期**：
  - 候选里的地点显示「来自网络 · 未实地核验」；
  - 生成后时间轴**第一站之前有"出发"段**；
  - 每站显示到达/离开时间、停留时长、到下一站的交通方式与耗时。
- **判定**：有出发段、有时间、交通耗时非空即通过。
- **常见失败**：没有起点时**不该**编造出发段（这是刻意的，宁可不说）——若看到凭空的出发段，反而是 bug。

### 3.2 少停/多停/不去了

- **操作**：点某一站的「少停一会儿」/「多停一会儿」/「不去了」。
- **预期**：弹出候选方案（含结束时间变化），必须**确认**才生效；点「保持原计划」不改变任何东西。
- **判定**：不确认不生效 = 通过。

### 3.3 一句话修改行程

- **操作**：第二个输入框输入 `不去最后一个地方了，改去哈工大` → 提交。
- **预期**：先出候选方案与理由（"替换最后一站"），确认后才改；如果搜不到具体校区，**整次不执行**并说明。
- **补充用例**：`去完哈尔滨学院想再去哈工大`（保留原站、在其后新增）；`再少停十分钟`（针对刚改的那一站）。
- **判定**：任何修改在确认前都不写库（退出重进还是原行程）。

### 3.4 进度与导航

- **操作**：在站点上点到达（「到了」）→ 点「开始导航」。
- **预期**：到达后进入下一站；导航页有真实路线折线、转向指引；最后一站到达后退出导航、不残留旧折线。
- **判定**：旧站点的路线与指引必须被清掉。

### 3.5 语音输入（行程页两个输入框都要测）

- **操作**：点输入框内左侧话筒 → 说一句话 → 再点一次结束 → 文字出现在框内 → 手动点提交。
- **预期**：
  - 说话时**实时预览**文字，说完点结束后最终文字回填**一次**；
  - 转写可编辑，不自动提交；
  - 录音中改点文字区 = 取消本次识别、保留原文字。
- **判定**：录音结束后不应自动发送；文字可编辑。
- **常见失败**：提示"录音分片格式不正确"→ 检查是否用了旧 SDK；提示连接失败 → 检查 `wss://asr.cloud.tencent.com` 是否在 socket 合法域名里。

## 四、小队与邀请 `[双机]`

### 4.1 建队与邀请码入队

- **操作**：A：「我的」→ 小队面板 →「创建小队」。B：同一位置输入 A 的 6 位邀请码 →「加入小队」。
- **预期**：两边人数都变 2；B 的个人行程**不受影响**（入队不覆盖个人路线）。
- **判定**：
  - B 自己的行程还在 = 通过；
  - 入队后**不该**自动开启位置共享（这是隐私要求）。

### 4.2 邀请分享与小程序码

- **操作**：A：「我的」→ 小队 →「邀请同伴 / 小程序码」→ 进入邀请页 →「生成邀请小程序码」→「保存小程序码」。
- **预期**：能生成图片并保存到相册；B 用微信扫这张码 → 先看到**邀请预览**（队伍名、成员数），点确认才入队。
- **判定**：
  - 预览阶段**不能**看到成员昵称以外的位置信息；
  - 撤销邀请后，同一个码再扫应提示失效；
  - 7 天后失效（可用「更新邀请」验证旧码失效）。
- **常见失败**：`wxacode.getUnlimited` 权限没部署 → 明确报"没有权限"，不是"图片无效"。

### 4.3 权限与退出 `[双机]`

- **操作**：A 移除 B（或 B 自己退出）→ B 立刻刷新「队伍」页。
- **预期**：B 看到"你不是该小队成员"类提示，队伍卡片清空，聊天输入框消失，**不能**再读位置与消息。
- **判定**：退队后立即失去访问权（不缓存成员身份）是设计目标，必须当场生效。

## 五、队伍页位置共享（A 单人 + 双机各一轮）

### 5.1 必须"主动开启"才共享

- **前置**：全新账号，从未开启过共享。
- **操作**：「我的」→「自动共享位置」。
- **预期**：先出现**用途说明 + 同意**，用户主动确认后才开启；开启后进入「队伍」立即定位并上传。
- **判定**：
  - 同意前**没有**任何坐标上传（B 的地图上看不到 A）；
  - 同意后才出现 A 的头像图钉；
  - 升级前的老账号（标记过共享但没有本版同意）**视为关闭**，需要重新主动开启。

### 5.2 移动与静止节流

- **操作**：A 在户外走动约 100 米（或开车绕一小段），停在原地 2 分钟。
- **预期**：移动时约 15 秒处理一次、位移 ≥20 米才上传；静止时每 60 秒更新一次。
- **判定**：B 的地图上 A 的图钉**跟着动**，且不是每 15 秒无条件刷一次。
- **注意**：这是策略而非精确指标，判定看"有没有明显跟随"和"静止时是否还在频繁跳"。

### 5.3 关闭共享与后台暂停

- **操作**：A 关闭「自动共享位置」；然后 A 把小程序切到后台。
- **预期**：关闭后 B 的地图上 A 的图钉立即消失（或明确显示"已关闭共享"）；切后台后 B 再刷新，A 的位置**不再更新**。
- **判定**：切后台仍持续更新 = 不过（本项目不申请后台定位）。

### 5.4 位置过期显示

- **操作**：A 关闭共享或让位置超过保留期；B 查看队伍页。
- **预期**：过期位置以**半透明头像**显示，标签写明「上次位置（已过期）」，不会静默消失。
- **判定**：静默消失 = 不过（用户会去错误的位置找人）。

### 5.5 重名不串人 `[双机]`

- **前置**：A、B 都把昵称改成同一个（例如「同名」）。
- **操作**：两人都开启共享，站在不同位置。
- **预期**：地图上两个图钉各自带自己的昵称；标签互相错开；A 发消息时气泡只出现在 A 的图钉旁。
- **判定**：出现"消息挂到同名队友身上"= 不过（关联用的是服务端稳定键，不是昵称）。

## 六、集合全流程 `[双机]`

这一节是最核心的协同链路，建议完整走一遍。

### 6.1 推荐集合点

- **操作**：A 在「队伍」页点「① 推荐一个集合点」。
- **预期**：给出集合点候选（按成员步行时间排序），地图上出现橙针与虚线；每个候选标注「个人参考：直线距离乘绕行系数估算」。
- **判定**：
  - 候选里会明确"这只是估算"，不会宣称是真实路网推荐；
  - 库里没有可用地点时**回退到地图 POI 检索**（不是直接失败）。

### 6.2 手动选点

- **操作**：点地图右下角 `✛` → 拖动地图把中间图钉对准位置 → 点「定这里」。
- **预期**：集合点更新为所选位置；退出选点模式后中间图钉消失、由地图标记表示。
- **判定**：拖动过程中图钉固定在屏幕中心不动，地图在底下滑。

### 6.3 发起集合

- **操作**：设置集合时间（默认当前时间，需要手动调到未来）→ 点「② 发起集合」。
- **预期**：生成集合任务；B 的「队伍」页出现该集合（地点、时间、状态「等待确认」）。
- **判定**：集合时间若是过去时间应被拒绝。

### 6.4 确认与到达 `[双机]`

- **操作**：B 点「确认集合」；A、B 分别点「我已到达」。
- **预期**：
  - 状态依次为「等待确认」→「已确认」→「全员到齐」；
  - 单人确认时**不应**显示"集合已确认"（要全员确认或队长确认后才算）；
  - 最后一人到达时写入"全员到齐"时间。
- **判定**：两人交替点确认，状态与人数不错乱（并发确认是自动化测过的，这里验界面）。

### 6.5 取消集合

- **操作**：队长点「取消本次集合」。
- **预期**：双方状态都变「已取消」；地图上集合点针消失；不能再用它做出发检查。
- **判定**：取消后仍能"准备出发"= 不过。

### 6.6 出发检查

- **操作**：点「准备出发 · 检查后续行程」。
- **预期**：返回检查结果（路线是否仍可执行）；检查有效期为**两分钟**，刷新或调整路线后需重新检查，再点「确认现在出发」。
- **判定**：两分钟后仍能直接出发 = 不过。

### 6.7 照片取集合点（可选，消耗高德配额）

- **操作**：选中集合点后点「正在取照片…」类按钮（`fetchPhotos`）。
- **预期**：集合点图钉换成该地点照片；**每次只针对一个地点**；照片标注“来自网络 · 未实地核验”。
- **判定**：反复点同一地点第二次应走缓存、不再耗配额。

## 七、队伍聊天 `[双机]`

### 7.1 文字消息

- **操作**：A 在地图下方输入框打字 → 发送。
- **预期**：
  - B 在地图左下角看到头像 + 气泡（只显示最近两条）；
  - A 自己的气泡出现在 A 的那一侧；
  - 点气泡**不跳页**、不改变集合点。
- **判定**：气泡内容与发送一致；昵称允许重名。

### 7.2 坐标消息（消息浮在队友图钉旁）

- **操作**：B 发送一条短消息，A 观察地图。
- **预期**：A 的地图上，B 的头像上方浮出消息气泡，**姓名标签保持白底中性色不被改写**；约 8 秒后消息消失、恢复姓名标签。
- **判定**：
  - 姓名**不能跟着变成蓝字**、也不能和消息挤进同一个框（这是历史上修过的 bug，要专门看）；
  - 无共享位置、共享已关闭、位置已过期的队友不弹坐标消息；
  - 同一人连发两条时后一条替换前一条。

### 7.3 语音转文字

- **操作**：点输入框内左侧话筒 → 说一句 → 再点结束 → 修改错字 → 发送。
- **预期**：与 3.5 一致；录音时话筒区域显示录音态，改点文字区取消录音并保留原文字。
- **判定**：转写必须可编辑后才发送，不自动发送。

### 7.4 发送失败与重试

- **操作**：断网时发送一条消息 → 恢复网络 → 点重试。
- **预期**：保留草稿与同一条消息编号；重试只产生**一条**消息，B 那边不会出现两条。
- **判定**：出现两条 = 不过（消息编号在事务内去重）。

> 7.4 依赖网络操作，可与第 12 节合并执行。

## 八、订阅消息（本次新增，重点）`[双机]`

> **前置**：P-06、P-07 已满足，且 `api` 已重新部署（包含 `lib/subscribe/*` 与 `actions/subscribe.js`）。
> 若模板未启用，本节全部标"跳过"，**不要标通过**。
> **注意**：每次点击「开启」都会消耗用户一次实际授权额度，请不要为了试而反复点。

### 8.1 订阅入口与授权

- **操作**：A 在「队伍」页点「订阅提醒」→ 面板展开，显示三类提醒（活动集合通知 / 活动状态变更通知 / 消息未读提醒）→ 点「消息未读提醒」右侧的「开启」。
- **预期**：
  - 弹出微信原生订阅授权框（**不是**小程序自绘弹窗）；
  - 点"允许"后该行变「已开启」，底部提示"已开启「消息未读提醒」提醒（每次同意大约可用一次）"；
  - 点"拒绝"时该行保持「未开启」，提示"没有开启…"，**不弹错误**。
- **判定**：
  - 授权框必须由用户点击触发（进页面就弹 = 违规）；
  - 面板底部常显"已同意 ≠ 一定送达"的说明。
- **失败判据**：点「开启」无任何反应 → 检查 `subscribe.status` 是否返回了 `templateId`、以及模板是否启用。

### 8.2 集合通知

- **操作**：A 已开启「活动集合通知」；A 发起一次集合（6.3）。
- **预期**：**A 自己不收**（发起人不推自己）；B（已开启该模板）在**关闭小程序**的状态下收到微信服务通知，内容含活动名称、集合地点、集合时间。
- **判定**：
  - 关闭小程序后才算真正验到云端推送（前台定时器不算）；
  - 通知里的时间格式为 `YYYY-MM-DD HH:mm`。
- **失败判据**：B 收不到 → 看 `notice_log` 里该事件的 `status`：`skipped/NO_INTENT` = B 没订阅；`failed/INVALID_ARGUMENT` = 字段编号或长度问题；`failed/…没有权限` = P-06。

### 8.3 集合状态变更通知

- **操作**：B 完成"全员确认"或有人点「暂不参加」。
- **预期**：其余成员收到状态变更通知（温馨提示、变更原因、变更时间）。
- **判定**：
  - **单人确认时不应收到**"集合已确认"（任务仍是"等待确认"，发出去就是假消息）；
  - 同一状态不重复通知。
- **常见误解**：改集合时间/地点**不是**状态变更，不该用这个模板（用途被收窄了）。

### 8.4 未读消息提醒

- **操作**：A、B 都开启「消息未读提醒」。B 让小程序**切到后台或关闭**，A 发一条消息。
- **预期**：B 收到"消息未读提醒"，内容含消息摘要、发送时间、发送人昵称。
- **判定**：
  - 连发 3 条，B 只应收到 **1 条**通知（60 秒窗口合并，一次授权只花一次）；
  - 60 秒后再发，才会产生下一次提醒；
  - **B 已经在小程序里看到消息后，不再被提醒**（已读的人不推）。

### 8.5 通知点击落地

分三条路径，都要测：

| 路径 | 操作 | 预期 |
|---|---|---|
| 同队 | B 收到通知后点击，且 B 当前活动队伍就是该队 | 进入「队伍」页，顶部提示"已从提醒回到队伍" |
| 异队 | B 当前活动队伍是另一个人建的队，点击旧队通知 | **先鉴权、通过后再切**：提示"已切换到提醒对应的队伍"，成员/集合/消息都换成新队伍 |
| 已失效 | A 把 B 移出队伍后，B 再点之前的通知 | **不切换**，提示"这条提醒所属的队伍已不可访问…"，右侧出现「去切换队伍」可点 |

- **判定要点**：
  - 异队/失效两条路径都必须走真实点击，不能用"我自己切 tab"代替；
  - 失效时**不能**把用户留在空白队伍页；
  - 落地页 `crewId` 只用来定位队伍，**不能**凭它直接展示消息正文（正文必须重新鉴权后取）。
- **补充**：若从通知冷启动（小程序已完全退出），属于最容易漏的路径——请专门测一次"杀进程 → 点通知"。

### 8.6 集合通知里的集合已结束

- **操作**：A 发起集合 → 出发/取消 → B 点击之前那条集合通知。
- **预期**：落地后提示"这条提醒对应的集合已结束或已取消"，不假装定位到集合。
- **判定**：仍显示那场旧集合 = 不过。

### 8.7 关闭提醒

- **操作**：面板里点「关闭」。
- **预期**：该行变「未开启」；之后同类事件不再给该用户推送。
- **判定**：状态持久化（退出重进仍是未开启）。

## 九、统一游览助手（A 单人 + 双机各一轮）

入口：各页右下角的悬浮按钮（可拖动）。轻点打开助手页。

### 9.1 文字提问与资料检索

- **操作**：输入 `中央大街的历史` → 提问。
- **预期**：先检索、再回答，回答里带**来源链接**（可点「复制来源链接」）；不编造没有来源的内容。
- **判定**：无来源却给出确定性结论 = 不过。

### 9.2 地点确认（不确认不行动）

- **操作**：输入 `想去哈尔滨学院` → 助手给出候选 → 点「确认这个地点」。
- **预期**：确认前不写行程、不发起集合；确认后才进入下一步（选起点/时长）。
- **判定**：没确认就生成行程 = 不过。

### 9.3 行程修改需用户确认

- **操作**：输入 `把最后一站换成哈工大`。
- **预期**：给出候选与理由 →「选择并确认此方案」才生效；「放弃本次修改」保持原样。
- **判定**：与 3.3 同一条纪律。

### 9.4 集合点接续

- **操作**：助手回答"准备集合点" → 点「用作集合点」。
- **预期**：返回「队伍」页，中心图钉已定位到该点，**没有**自动发起集合（仍需用户设置时间再点「② 发起集合」）。
- **判定**：直接建集合 = 不过。

### 9.5 照片入口

- **操作**：点「拍照 / 选图」→ 拍照 → 点「提问 / 发送」。
- **预期**：拍照只本地预览，**主动提问才上传**；识别结果可点「查看位置」。
- **判定**：一拍照就自动上传 = 不过（流量与隐私）。

### 9.6 导航

- **操作**：点「导航到下一站」/「导航到集合点」。
- **预期**：进入导航态，有真实路线与转向指引；「用微信地图打开（有语音）」可跳出到微信地图。
- **判定**：没有真实路径时**不给假折线**（宁可没有）。

### 9.7 人群计数（YOLO，需云端服务）

- **操作**：点「YOLO 人群计数」（需 `YOLO_BASE_URL`/`YOLO_API_KEY` 已配）。
- **预期**：返回人数与置信度。
- **判定**：返回 0 人不能直接判为"功能坏了"，需用有人画面再测；服务未配时应明确提示未配置，而不是静默失败。

## 十、OCR 与照片识别

入口：助手页「拍照 / 选图」；集合点处的「拍照 / 选图」（`photo-meeting` 组件）。

- **操作**：拍一张含文字的招牌 → 点「识别这张照片」。
- **预期**：返回文字与置信度；可点候选「选为集合点」。
- **判定**：
  - 识别结果里的地点坐标来自真实 POI 检索，不是模型编的；
  - 图片不做持久化存储（这是隐私承诺）；
  - 服务未配置时提示"未配置/未开通"，不吞错。
- **失败判据**：`OCR_NOT_CONFIGURED` = 环境变量没配；`UPSTREAM_OCR_FAILED` = 腾讯云侧问题（看 `errCode`）。

## 十四、失败时怎么定位（速查）

| 现象 | 先看这里 |
|---|---|
| 接口报"未知的接口" | `api` 没部署最新版（P-01） |
| 报"没有权限" | `config.json` 的 `permissions.openapi` 没生效（P-06） |
| 订阅发送失败、`47003` | 字段编号/长度与后台模板不符（P-07、`lib/subscribe/templates.js`） |
| 订阅发送失败、`43101` | 用户没订阅或次数用尽 —— 这是**正常业务状态**，不是 bug |
| 收不到任何通知 | 先查 `notice_log`：`skipped/NO_INTENT`（没订阅）、`skipped/ALREADY_SENT`（窗口内已发）、`failed/*`（发送失败）、`unknown`（结果不明，不自动重试） |
| 地图/公交/照片没数据 | 对应 Key 未配或没开通；用「后端自检」看 `configured`，再用探针看权限 |
| 云数据库报 `-502005` | 集合不存在 → 执行 `ops.initDb`（P-04） |
| 重复写入没被拦住 | 唯一索引没建（P-05） |
| 集合推荐为空 | 地点库为空 + 地图 POI 回退也失败 → 看 `MAP_KEY` |
| 页面白屏 | 基础库过低 / `app.js` 云开发初始化失败（「我的」页会有错误文案） |
