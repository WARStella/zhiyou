## 一、怎么跑

```bash
# 项目唯一入口（在 zhiyou/ 下执行）
node scripts/run-tests.js
```

**为什么不用 `node --test test/`**：内置测试运行器会为每个测试文件 spawn 子进程并走管道 stdio，在受限沙箱下会以 `spawn EPERM` 失败。`scripts/run-tests.js` 在**单进程**内依次 `require` 全部 `*.test.js`，等价且更快（见该文件头部注释）。

**前置条件：没有。** 不需要 AppID、不需要云开发环境、不需要联网、不需要真实密钥。这是刻意设计：

- 领域算法是纯函数；
- 仓储层可替换（内存 / 云数据库）；
- 所有外部服务都通过**注入点**替换为替身，测试不会真的去连腾讯地图、高德、腾讯云 ASR/OCR、DeepSeek 或 YOLO。

因此整套回归可以在拿到任何云端配置之前就跑完，也可以在没有网的机器上跑。

**读失败信息时**：`scripts/run-tests.js` 会先打印每个文件的分节标题，再在结尾汇总失败项。失败信息里 `test at test/xxx.test.js:行号` 指的就是具体用例。

## 二、四层结构

测试按"离真机有多远"分层。这个划分本身就是一条纪律：**越往下越靠替身，越往上越靠真实代码路径**。

| 层 | 覆盖对象 | 替身/真实 | 不覆盖 |
|---|---|---|---|
| ① 纯函数与领域算法 | `domain/`、`lib/` 的算法部分（时间线、可行性、规划器、地理、步行估算、模式选择） | 无 IO，直接调用 | 存储、鉴权、网络 |
| ② 接口层 | `actions/` + `lib/invoke.js` + 仓储 | **真实 invoke 路径** + 内存仓储 + 注入的服务替身 | 云数据库的真实事务/索引行为 |
| ③ 小程序页面与组件 | `pages/*`、`components/*`、`utils/*`（前端） | `test/page-harness.js` 造页面实例、`wx` 与 `api` 替身 | 真实渲染、样式、真机手势 |
| ④ 工程守卫 | 配置、文档、WXML/WXSS 静态约束、注入点清单 | 读源码做静态断言 | 运行时行为 |

第 ② 层是这套测试最有价值的地方：**测试调用的是与线上完全相同的 `invoke` 与 `actions` 代码，只有仓储实现不同**。这也是"没有 AppID 也能开发"的验证方式 —— 否则本地测试跑的不是线上真正执行的代码。

## 四、测试**不覆盖**什么（诚实清单）

这一节比上一节重要：把"没测"说清楚，才不会把本地绿灯当成发布条件。

| 没覆盖的 | 说明 | 谁来兜 |
|---|---|---|
| **真机渲染与交互** | 页面测试只验"调了方法之后 `data` 对不对"，**不渲染 WXML**。布局、`cover-view` 层级、手势、滚动、`map` 组件原生行为都没测 | 真机验收清单 |
| **云数据库的真实行为** | 事务、索引、`-502005` 缺集合、安全规则、并发在云上的真实表现，本地一律用内存仓储 | 部署后按 `ops.initDb` 手工建索引，真机连跑 |
| **微信真实发送** | 订阅消息、小程序码、内容安全，全部用替身；本地**不会**真的发出通知 | 部署后由两名成员真机核对 |
| **真实上游服务** | 腾讯地图、高德公交/照片、腾讯云 ASR/OCR、DeepSeek、YOLO 一律不连；探针类用例只验"没配 Key 时不发请求、错误指向何处" | `map.probe`/`transit.probe`/`photo.probe`/`ai.probe` 在真环境跑 |
| **密钥是否有效** | 测试只验"Key 不出现在返回与日志里"，验不了 Key 有没有权限 | 各 provider 的 probe |
| **隐私合规与审核规则** | 隐私指引、类目、订阅模板审核状态属于后台配置，代码测不了 | 人工核对后台 |
| **视觉与文案质量** | 没有截图对比，没有 i18n 检查 | 人工走查 |

> 一句话口径：**本地全绿说明"逻辑与契约没被破坏"，不说明"线上能用"。**

## 五、写新用例的约定（为什么这么要求）

这些约定不是风格偏好，每一条都对应一次实际踩过的坑（详见 `开发日志`）。

1. **接口用例必须走真实 `invoke` 路径**，不要直接调 action 函数。否则测的不是线上真正执行的代码（鉴权、幂等、错误结构、事件日志都在 `invoke` 里）。
2. **外部服务用注入点替换，不要设环境变量**。环境变量注入不了"上游故障"这种状态，还会让产品代码为了可测而读一个只对测试有意义的变量。
3. **新增注入点必须同时改 5 处**：`lib/invoke.js` 的 `SERVICE_INJECTIONS`、`api/index.js`（线上传 `null`）、`test/helpers.js`、手写 `invoke` 上下文的测试、以及本条守卫测试。漏改的表现是"替身被静默丢掉、动作层回落到真实实现"，报出来的却是看似无关的"Key 没配置"。
4. **绝不连真实上游、绝不用真实订阅次数**。订阅消息一律注入 `lib/subscribe/fake.js`；用用户的授权额度做回归等于把额度当耗材。
5. **替身必须与真机同形**：小程序 API 是回调风格（`{success, fail}`），替身写成 Promise 会让页面走进另一条分支，于是测出来不是真机行为。
6. **前端测试加载真页面文件**：`test/page-harness.js` 的 `loadPage()` 会 `require` 真实的 `pages/*/index.js`，只替换 `wx` 与 `utils/api`。不要为新测试复制一份页面逻辑。
7. **静态守卫别删**：`wxml-guards`（WXSS 属性选择器、WXML 方法存在）、`app-config-guard`（权限用途 ≤30 字、四件套）、`injection-points`（注入点清单）、`audit-regressions` 的"所有 action 都在接口清单里" —— 这些是防"静默失效"的，不是形式主义。
8. **测"不该发生的事"**：多数真实事故是"少做了某一步却不报错"（漏画图钉、漏推进已读、把旧消息当新消息）。写用例时优先问"如果这一步不做，界面上会不会看不出来"。

## 六、基础设施

| 文件 | 作用 |
|---|---|
| `scripts/run-tests.js` | 唯一入口：单进程依次 require 全部 `*.test.js`，规避沙箱 `spawn EPERM` |
| `test/helpers.js` | `makeWorld()` 造"内存仓储 + 真实 invoke"的世界；`makeCrew()` 建三人小队并各自开启位置共享；`expectOk`/`expectFail` 统一断言 |
| `test/page-harness.js` | `loadPage()`/`loadComponent()`：截取 `Page()`/`Component()` 选项，给可跑的 `setData`，替换 `wx`、`getApp`、`utils/api`；留 `__calls`/`__wx`/`__storage` 供断言 |
| `test/fixtures/` | 地点夹具、意图样例、上游响应录音（真实录音，不是编的） |
| `test/replay-runner.js` | 把团队流程回放案例翻译成机器判定 |

**内存仓储刻意模拟了云数据库的两个行为**，否则会"本地对、线上错"：
`updateCas` 版本不匹配时 `updated === 0` 且不写入；`update` 只做浅合并。唯一索引同样在内存侧模拟（冲突抛 `errCode -502001`）。
