# 2026-10-15 体验版反馈修复

## 行为与验证

| 反馈 | 修复后行为 | 真机验收 |
| --- | --- | --- |
| 需求先后顺序丢失 | 预选按 `autoPick.itemIds` 顺序读取，不按候选距离排序回填 | 输入“先去 A 再去 B”，即使 B 更近，游览顺序仍为 A → B |
| 优化顺序冲突 | 生成前比较两种顺序；不同则弹窗列出，用户选择后再调用 `trip.plan` | 分别选“需求顺序”和“优化顺序”，核对时间轴；相同时不弹窗 |
| 集合缺少参数 | 先用 `team.current` 找任务 ID，再以 `meetTaskId` 调 `meet.get`；读 `data.meetTask`；确认、到达、取消和出发传版本号；拒绝走 `meet.confirm` | 三账号完成发起、确认、到齐、检查、出发；另测拒绝和取消 |
| 队员位置不显示 | 共享开关传 `sharing`；读个人共享状态；主动共享可开启并上报；每 15 秒刷新；过期位置保留并标注；可点“查看全队位置” | A 共享后 B 地图显示 A；关闭后图钉消失；跨视野可一键查看 |
| 公交过于冗杂 | 摘要只留方式、时长、线路号、总票价，例如“公交 39 分钟 365/643/815 总价6元” | 查看出发段、当前路段、站间路段及逐段选择器 |
| 地铁缺失 | 新增 `subway` /“地铁优先”；从同一次高德响应中提取含地铁的最快方案；时间轴按实际方案显示“地铁”或“公交＋地铁” | 对有地铁方案的两点选择“地铁优先”；无方案时显示原因 |

顺序优化依据地点直线距离：最多 10 个待排序地点时求最短距离顺序，更多地点采用近邻建议；未取得定位时固定用户第一站。这不是实时路网最短耗时的保证，弹窗中已标注距离估算。每段实际交通耗时仍由云端地图服务计算。

位置采用主动上报，不持续追踪。超过服务端时效阈值的位置标注“上次位置（已过期）”，不会冒充实时位置。地铁候选只取上游实际返回方案，可能含公交接驳；未返回地铁方案时说明不可用。

缓存现在保留公共交通线路和票价；缺少这些字段的历史公交缓存会重新请求，避免只显示耗时而丢失地铁和票价信息。
