### ⚠️ 一个必须记住的坑：额度要**分配**给 Key

2026-10-13 实际踩到：新建 Key 后调用返回 `status: 121 此key每日调用量已达到上限`，
但当天只有 4 次有效调用。**原因不是额度用完，而是账户额度没有分配给 Key。**

```
控制台 →「配额管理」→「账户额度」→ 点「一键分配」
（或对单个接口点「配额分配」）
```

分配前每一行显示 `0 / 6,000`（已分配 / 总额度），分配后变成 `6,000 / 6,000`。

**排查口诀**：遇到 `status: 121` 先看「账户额度」页的**分子**是不是 0，再怀疑额度真的用尽。

> 该提示已做进代码：`lib/map/tencent.js` 的 `STATUS_HINTS[121]` 会在探针结果里直接给出这段指引。

> **地图 API 是唯一可能因"算法反复调参"而超额的部分**。
> 对策：`lib/geo.js` 优先使用踏勘实测的 `place.walkableTo` 缓存，减少实时调用；
> 并在 `events.mapApiCalls` 里逐次计数（已实现），11/8 可直接统计。

### 环境名称对代码零影响

环境自动创建为 `cloud1`，不需要删掉重建。原因：

```js
// 云函数：用"我被部署到的那个环境"
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
```

小程序端 `wx.cloud.init()` 不指定 `env` 时使用默认环境。因此**环境叫什么名字不影响任何代码**，
"环境ID 创建后不可修改"这一限制在本项目中不构成任何麻烦。

## 5. 经验记录：平台"开通"流程的默认选项

**2026-10-13**：开通云开发时，流程默认展示了 ¥19.9/月 的基础套餐（含「购买」按钮）。

虽然本次**未产生实际扣费**（当前为免费体验版，按量付费与自动续费均为关闭），
但这类界面在后续还会遇到。处理原则：

1. **看到价格数字时，先分清"报价"和"账单"** —— 报价只说明可以买，不代表已买。
   判断是否付费要看**订单页**，不是套餐页的价格。
2. **`按量付费` 与 `自动续费` 两个开关保持关闭**，除非明确需要。
   `按量付费` 开启后不再限制资源使用，超出部分直接计费。
3. **不要因为"额度一样"就选付费版** —— 免费版 40,000 点/月与 ¥19.9 版额度相同。
4. 本项目 11/12 验收要求"成本可核算"，因此**每一次涉及付费的选择都要留记录**。

> 同类默认选项在 W4 走正式发布审核时还会遇到（如认证、加急审核等），届时同样先截图确认。
