| 备选 | 说明 |

## 6. 找不到「云开发」入口怎么办

新手在开发者工具里找不到云开发按钮，**最常见的原因不是"没找到"，而是"它还没出现"**：
云开发是基于小程序账号的能力，**基本信息未完成时该入口可能不显示或被禁用**。

按可靠度排序的四个入口：

| # | 位置 | 说明 |
|---|---|---|
| ① | 文件树里 `cloudfunctions` 后面那行「**(未选择环境)**」 | 这行文字本身就是环境选择器，点它会弹出环境列表与「新建环境」 |
| ② | 右键 `cloudfunctions` 目录 | 菜单里有环境相关子菜单（新建/切换环境、上传并部署、新建云函数） |
| ③ | 菜单栏「工具」 | 找云开发相关项 |
| ④ | 顶部工具栏「上传」右侧那一排小图标 | 「云开发」通常是**云朵形状的图标**，不是文字按钮 |

**先做完基本信息再找**，能省掉大量困惑。

### 关键：卡在这里不阻塞今天的验收

| 目标 | 需要云环境吗 |
|---|---|
| 算法正确性（时间线、可行性、候选生成、三时间分离） | ❌ 不需要，本地测试覆盖 |
| 权限、幂等、版本冲突 | ❌ 不需要，本地测试覆盖 |
| 真机联调（W2 的三机联调） | ✅ 需要 |

**云环境的作用是"联调"，不是"正确性验证"。** 联调最早在 W2 三台真机到位时才开始，
所以基本信息审核等待期不会拖慢 W1 的开发线。

## 7. 已踩坑：小程序被授权给第三方平台，云开发控制台被禁用

**发生日期**：2026-10-13（W1 第一天）

### 症状

在开发者工具里打开云开发控制台，返回：

```json
{
  "apiIdentifier": "qbase/GetQbaseInfo",
  "code": "80210",
  "message": "[UPSTREAM] Upstream error (ret=80210)",
  "reason": "小程序已授权给第三方平台，无法使用云开发控制台",
  "wxAppName": "智旅灵游"
}
```

### 成因（已定位）

小程序在微信公众平台里被授权给了第三方服务商 **腾讯位置服务**。

| 字段 | 值 |
|---|---|
| 第三方平台 | 腾讯位置服务 |
| 授权时间 | 2026-10-13 11:36 |
| 阻塞项 | 权限清单中的「**小程序云开发管理**」 |
| 授权权限总数 | 四十余项（含小店、直播、微信支付、广告、物流、电子票据等，**全部与项目无关**） |

授权状态下：云开发控制台被禁用（云开发资源由该服务商代管），
后台「下一步」操作被卡住（表现为「请先完成小程序基本信息填写，才能继续下一步」）。

**直接原因**：为准备 10/14 的地图接口验证，在服务市场授权了「腾讯位置服务」。

### 解法

```
mp.weixin.qq.com → 左侧最下方「设置」→「第三方设置」→ 第三方平台授权管理
→ 选中该平台 →「解除授权」
```

也可用「管理授权」只取消「小程序云开发管理」一项，但**不推荐** ——
其余四十余项权限与本项目无关，按最小权限原则不应保留。

**解除后必须重启微信开发者工具**（退出重新登录），否则控制台会缓存旧的授权状态。

> 出处：微信开放社区
> [该小程序帐号已授权服务商使用云开发资源](https://developers.weixin.qq.com/community/minihome/doc/000a2642d2c8d85b875acb1dc5d000)、
> [云开发不能使用怎么办？](https://developers.weixin.qq.com/community/minihome/doc/000c8ce58706e06dd8012e3c86b000)

### 关键认知：地图能力不需要这个授权

本项目调用腾讯位置服务的方式是：**云函数内**用 Key 调 **WebService API**（步行路线规划）。
所需条件仅为：

```
lbs.qq.com 注册开发者账号 → 创建 Key → 为该 Key 开启 WebService API
```

**不需要把小程序授权给腾讯位置服务。** 小程序端展示地图用微信**原生 `map` 组件**，同样不需要。

据此可写入答辩材料「安全与最小权限」一节：**我们核对过每一项第三方授权，无一项是超额的。**

### ⚠️ 取消授权前必须确认

| 小程序的注册方式 | 取消授权是否安全 |
|---|---|
| 自己在本平台逐步注册 | ✅ 安全（本次即属此类） |
| 通过建站平台／低代码平台／代注册服务注册 | ⚠️ 该平台可能靠此授权代管，取消前先确认它是否还负责注册或认证 |

**先看清"授权的第三方是谁"和"授权了哪些权限项"再动手。**

### 兜底方案

若授权无法解除、或解除后发现小程序状态异常：**重新注册一个干净的个人主体小程序**。
成本是免费 + 一个未用过的邮箱，代价是已通过的名称需要重新申请（1–3 个工作日）。

### 为什么这条要记录

计划书**风险 0** 写明：「主体与能力资格影响相关能力可用性与发布路径，W1 第一件事确认……
越晚发现，可回旋的余地越小。」

本项正是在 W1 第一天、写业务代码之前暴露出来的**前置风险**。
若拖到 W2 三机联调时才发现云开发不可用，代价会大得多 —— 这条记录即该判断的验证。
